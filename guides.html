📖 使用教程

从「查一个 IP」到「用数据排查问题」

第 1 步：查询一个指定 IP

打开首页，在输入框中填入 IPv4 地址，例如 8.8.8.8，点击「查询」。页面会返回十个字段：国家/地区、省份/州、城市、邮编、ASN、运营商、组织、经纬度、时区，以及一个可直接打开的地图链接。

注意：只支持公网 IPv4。像 192.168.1.1 这类内网地址没有全球唯一归属，工具会直接报错——这是正确行为，不是故障。

第 2 步：查询自己的公网 IP

点击「📍 查询我的 IP」，工具会自动识别你当前的公网出口地址并查询。这一步常用于：

  • 确认代理是否生效：如果你开了 VPN 但查到的仍是本地城市，说明流量没走代理。
  • 确认运营商出口：家用宽带查到的城市，通常就是你所在城市的运营商核心节点。
  • 排查 NAT：若查到的城市与你的实际居住地跨省，多半是运营商做了跨区域地址复用。

第 3 步：读懂结果里的关键字段

十个字段里，有三个最容易被忽略、却最有信息量：

  • ASN：告诉你这个 IP 属于哪个网络运营实体。例如 AS15169 是 Google，AS13335 是 Cloudflare。如果访客 IP 的 ASN 是某云厂商，那它很可能是爬虫或机器人，而不是真实用户。
  • 组织（Org）：常能直接看出公司或机构名。结合 ASN 一起看，比单看城市可靠得多。
  • 时区：做跨时区业务时，可用它判断用户的作息区间，比用国家推断更准（例如美国跨多个时区）。

想系统理解这些概念，请看IP 知识文档。

第 4 步：用 API 做轻量自动化

本站提供同源 API，返回 JSON，适合脚本调用：

GET /api/ip?ip=8.8.8.8 — 查询指定 IP

GET /api/ip — 查询调用方自身 IP

一个最小可用的 curl 示例：

curl "https://locip.pages.dev/api/ip?ip=8.8.8.8"

结果会被边缘节点缓存（指定 IP 缓存 24 小时，自身 IP 缓存 5 分钟），因此重复查询同一地址响应极快。请勿高并发调用，上游数据源有频率限制。

实战：用 IP 查询排查网站异常访问

假设你的网站日志里出现大量请求，怀疑是爬虫，可以按这个顺序排查：

  • 取样本：从日志里挑出请求量最高的 10 个 IP，不要一上来就全量查。
  • 看 ASN：如果它们的 ASN 都属于同一家云厂商（如阿里云、AWS、DigitalOcean），基本可判定为服务器发起的自动化流量。
  • 看地理集中度：若集中在少数几个城市且 ASN 一致，更可能是机房而非真实用户分布。
  • 交叉验证：结合 User-Agent、请求路径与频率判断，不要仅凭 IP 归属地下结论——误杀真实用户的代价很高。
提醒：IP 定位是概率推断，可作为辅助信号，但不应作为封禁的唯一依据。这是使用这类工具最重要的一条原则。
